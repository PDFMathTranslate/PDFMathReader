# 资源占用开关实测比较

2026-10-05，Apple M3 Max，36 GiB RAM，macOS 27.0，开发版 Electron。同一份内置两页 PDF，原文显示、对照渲染模式、自动翻译关闭。开启和关闭各启动一个独立应用进程；每组依次测前台、非前台、最小化。状态稳定 3 秒后，以 1 秒间隔采样 10 次。

CPU 为应用进程树累计 CPU 时间增量 / 墙钟时间；100% 表示一个逻辑核。RSS 为主进程、渲染器、后端、GPU 等后代进程的 RSS 求和，可能重复计算共享内存，不能视为独占物理内存。位图为页面/缩略图画布及位图缓存分配量。

| 状态（kernel 空闲） | CPU 开启 / 关闭 | RSS 开启 / 关闭   | 位图开启 / 关闭 | Python kernel 开启 / 关闭 |
| ------------------- | --------------- | ----------------- | --------------- | ------------------------- |
| 前台静止阅读        | 0.93% / 1.13%   | 801.8 / 764.2 MiB | 85.1 / 85.2 MiB | 0 / 0 进程                |
| 非前台              | 0.47% / 0.85%   | 806.5 / 771.5 MiB | 0.0 / 85.2 MiB  | 0 / 0 进程                |
| 最小化              | 0.56% / 1.21%   | 744.4 / 727.4 MiB | 0.0 / 85.2 MiB  | 0 / 0 进程                |

这次短测的明确结果是：开启后非前台和最小化的位图分配归零；后台 CPU 样本较低。RSS 没有显示降低，开启组甚至高于关闭组。因此不能根据位图回收宣称应用总内存已降低，也不能把单轮 CPU 差异视为稳定比例。前台状态不改变绘制策略，两组差异主要反映运行间波动。

完整文档翻译在后台继续。阅读模式后台停止派发新任务，但已运行的任务继续完成。Fast / Precise 内核按页启动，没有常驻模型服务；空闲时两组都没有 Python kernel 进程。开关没有限制活动内核的线程数、并发数或强制终止进程。

原始数据：`resource-benchmark-on.json`、`resource-benchmark-off.json`。复现：`PDF_RESOURCE_SAVING=1 ./node_modules/.bin/electron . --smoke-test=resource-benchmark`，关闭用 `PDF_RESOURCE_SAVING=0`。

## 活动内核基线（独立于窗口测试）

真实已安装 Python 内核、单页三段英文、French、两线程，使用本地模拟 API（每请求等待 400ms），不产生付费请求。每个引擎两次独立未缓存任务。标记开启 / 关闭仅用于两轮的区分：后端没有该开关，执行路径完全相同，并非完整应用各窗口状态的活动翻译 A/B。因此数值差异不能归因于开关。

| 内核                   | 轮次标记 | 平均 CPU | 平均 RSS   | 峰值 RSS   | 完成耗时 | 完成三秒后进程数 / RSS |
| ---------------------- | -------- | -------- | ---------- | ---------- | -------- | ---------------------- |
| pdf_math_fast 1.9.12   | 开启组   | 113.8%   | 395.1 MiB  | 563.1 MiB  | 3.67s    | 0 / 0 bytes            |
| pdf_math_fast 1.9.12   | 关闭组   | 133.6%   | 474.0 MiB  | 629.5 MiB  | 3.03s    | 0 / 0 bytes            |
| pdf_math_precise 2.8.2 | 开启组   | 50.3%    | 1401.9 MiB | 2768.1 MiB | 22.74s   | 0 / 0 bytes            |
| pdf_math_precise 2.8.2 | 关闭组   | 59.8%    | 1604.5 MiB | 2884.2 MiB | 18.03s   | 0 / 0 bytes            |

CPU 按 250ms 采样中进程存活的区间计算，短进程在采样间退出可能漏记 CPU；RSS 包括内核后代进程，可能重复计算共享页。模拟 API 的延迟与真实模型服务不同。四次请求均 HTTP 200，生成有效 PDF。原始数据为 `kernel-resource-benchmark.json`，复现 `node server/kernel-resource-benchmark.mjs`。

窗口最小化或非前台时，完整文档模式中的活动内核继续执行；阅读模式停止派发新任务但已运行任务仍完成。开关不会降低当前 kernel 的线程数或模型占用。

后续默认值更新：未设置 `interactionMode` 时使用阅读模式；保存的 `comparison` 保留。本页窗口性能数据使用明确的对照模式，未因默认值更新重新测量。
