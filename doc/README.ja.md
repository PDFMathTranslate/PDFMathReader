# PDFMathReader

[English](../README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)
- **⌘1**、**⌘2**、**⌘3** で単ページ、2ページ、4ページのレイアウトに切り替えます。**⌘⇧1–9** は 10–90%、**⌘⇧0** は末尾に移動します。

macOS の Preview に着想を得たインターフェース、段落翻訳、数式を考慮した翻訳カーネルを備えたローカル PDF リーダーです。Vue 3、PDF.js、Electron で構築されています。

<img src="preview.png" alt="PDFMathReader の閲覧画面" width="70%">


## 最近の更新

- 複数の PDF をそれぞれ独立したウィンドウで開けます。各ウィンドウには固有の閲覧位置、翻訳処理、バックエンドプロセスがあります。1つのウィンドウを閉じても、他のウィンドウは動作を続けます。
- **File → Open recents...** からサムネイルギャラリーで最近の PDF を閲覧できます。文書を再び開くと、そのページ、スクロール位置、ズーム、レイアウト、サイドバー、原文/翻訳表示が復元されます。
- **File → Preference** または **Settings…** から既存の設定パネルを開けます。
- **Settings… → Appearance → Interface language** で、English、简体中文、日本語を切り替えられます。この設定は文書の翻訳言語とは別です。
- 検出された個々の領域をその場で原文と翻訳の間で切り替えられます。**Ultra fast**、**Fast**、**Precise** のいずれもシングルクリックで切り替えます。
- 仮想化されたページとサムネイル、上限付きのレンダリングキャッシュ、独立したレンダリング、レイアウト解析、翻訳により、大きな文書を読めます。

## クイックスタート

### デスクトップアプリを実行する

開発には Apple Silicon Mac 上の Node.js 22 を使用してください。

```zsh
npm install
npm run desktop
```

PDF を開き、**Settings…** または **File → Preference** を開きます。OpenAI API key を入力し、**Save key** を選択します。対象言語と翻訳カーネルを選びます。PDF の閲覧とレイアウトの確認にはキーは不要ですが、翻訳には必要です。

**Ultra fast** が含まれています。**Fast** または **Precise** を使用するには、`uv` をインストールし、Settings でカーネルを選択して **Install kernel with uv** を選びます。各数式カーネルはアプリが管理する個別の Python 環境を使用します。利用可能かどうかの確認では、パッケージをインストールしたりグローバルツールを変更したりしません。

### macOS アプリをビルドする

```zsh
npm run package:mac
```

`release/PDFMathReader-darwin-arm64/PDFMathReader.app` を開きます。パッケージ化されたアプリにはランタイムとローカルバックエンドが含まれているため、別途 Node.js をインストールしたり開発サーバーを起動したりする必要はありません。パッケージ化コマンドは、署名されていないローカル Apple Silicon ビルドを生成します。

デスクトップアプリは `OPENAI_API_KEY` と `OPENAI_MODEL` も受け付けます。Finder は通常、ターミナルの環境変数を引き継ぎません。ログインシェルの設定でパッケージ化されたアプリを起動するには、`Launch PDFMathReader.command` を使用します。

### ブラウザ開発

```zsh
read -s 'OPENAI_API_KEY?OpenAI API key: '; export OPENAI_API_KEY
npm run dev
```

[127.0.0.1:5173](http://127.0.0.1:5173) を開きます。起動前に `OPENAI_MODEL` を設定すると、デフォルトモデル `gpt-4.1-mini` を上書きできます。

バックエンドとリーダーのサポートロジックを確認し、フロントエンドをビルドするには、次を実行します。

```zsh
npm test
npm run build
```

## 機能

### 読み取りと文書管理

- 最大 50 MiB の PDF を開くかドラッグして読み込めます。パッケージ化された macOS アプリは Finder の **Open With** と、Dock アイコンへの PDF のドロップにも対応しています。
- 異なる PDF を独立したデスクトップウィンドウで読み取れます。各ウィンドウには固有のレンダラーとバックエンドプロセスがあります。
- サムネイルで移動し、ズームを変更し、幅または高さに合わせ、縦または横にスクロールし、1 行あたり 1、2、または 4 ページを選択できます。
- 開始ページまたは File メニューのギャラリーから最近の文書を再開できます。閲覧状態は文書ごとに保存されます。
- macOS では、**⌘N** で新しいウィンドウ、**⌘O** で PDF を開き、**⌘W** で現在の文書を閉じ、**Ctrl+W** でそのウィンドウを閉じます。Windows と Linux では、それぞれ **Ctrl+N**、**Ctrl+O**、**Ctrl+W**、**Ctrl+Shift+W** を使います。

macOS は統合ツールバー、ネイティブのトラフィックライト、vibrancy を使用します。Windows は Segoe UI のツールバーを備えたネイティブタイトルバーとメニューを使用します。Linux はデスクトップが管理するウィンドウ装飾、システムフォント、不透明なツールバーを使用します。Windows と Linux では、その他のリーダーショートカットで Command の代わりに Ctrl を使います。

### 翻訳

| 設定 | エンジン | 出力 |
| --- | --- | --- |
| Ultra fast | PDF Inspector | 元の PDF 上の段落オーバーレイ |
| Fast | PDFMathTranslate | 数式を保持した翻訳済み PDF ページ |
| Precise | PDFMathTranslate-next | より詳細な組版による翻訳済み PDF ページ |

Settings で対象言語を選択します。**完整翻译** は文書全体を翻訳します。**降低翻译请求** は、読み進める際に現在のページとその前後最大 2 ページを翻訳します。並列ページ数を 1–4、翻訳リクエスト数を 1–8 に設定できます。デフォルトはそれぞれ 2 ページと 4 リクエストです。

インターフェイス言語は **Appearance → Interface language** で個別に変更できます。変更するとリーダーのラベルとメニューが更新されますが、文書の翻訳言語は変わりません。追加のシステム文言と、より広いアクセシビリティ対応は今後の UX 作業です。

ツールバーの翻訳コントロールで、原文と翻訳済みコンテンツを切り替えます。すべてのカーネルで、検出された段落をシングルクリックすると、その場で原文と翻訳を切り替えられます。**Show paragraph boundaries** を有効にすると、検出された領域を確認できます。Settings から現在のページの失敗を再試行します。

レンダリング、レイアウト検出、翻訳は独立して実行され、結果は段落またはページの処理が完了するたびに表示されます。文書、言語、またはカーネルを変更すると、古くなった処理はキャンセルされます。ウィンドウを最小化または非表示にすると、レンダリングと閲覧モードの処理は一時停止します。文書全体の翻訳は続行します。

### ローカル処理と保存

PDF のレンダリングとレイアウト解析はローカルで実行されます。翻訳では文書テキストを OpenAI に送信するため、API 料金が発生する場合があります。数式カーネルは一時的なローカル PDF ファイルも作成します。翻訳結果とレイアウトメタデータはこのデバイスにキャッシュされます。

Settings で保存したデスクトップの API キーは、Electron の `safeStorage` と macOS Keychain による保護を使用して暗号化されます。保存したキーは `OPENAI_API_KEY` より優先されます。キーを消去すると、環境変数のフォールバックに戻ります。安全なストレージが利用できない場合、保存は無効になり、renderer API が保存済みキーを公開することはありません。

デスクトップデータは、`~/Library/Application Support/` 内のアプリのディレクトリに保存されます。

| 場所 | 内容 |
| --- | --- |
| `openai-key.enc` | 暗号化された API キー |
| `recent-documents.json` | 最近の文書のパス、プレビュー、閲覧位置 |
| `translations/` | キャッシュされたテキスト、翻訳済み PDF ページ、レイアウトメタデータ |
| `engines/` | 数式カーネルの環境とアセット |

開始ページの **Clear** を使うと、最近の文書履歴を削除できます。ブラウザ開発時の翻訳は `.cache/translations/` にキャッシュされます。キャッシュされた結果を消去するには、対応する翻訳キャッシュディレクトリを削除してください。翻訳キャッシュには、文書に由来するテキストが含まれる場合があります。バックエンドは `127.0.0.1` にバインドされ、デスクトップアプリはローカルリクエストを認証します。

### レンダリング性能

ページとサムネイルの DOM ノードは仮想化されています。リーダーは表示中のページとその両側最大 4 行をレンダリングし、サムネイルはサイドバーの表示領域付近で読み込まれます。ビットマップの再利用は 64 MiB、常駐ページキャンバスは 128 MiB に制限されており、メモリの圧迫時には遠くで先読みされたキャンバスから先に解放されます。

各 PDF はローカルバックエンドに一度だけアップロードされ、その後のページ要求では文書 ID を使用します。PDF.js とレイアウト解析は必要に応じて読み込まれます。

ウィンドウのリサイズとサイドバーの切り替えではレイアウトをリアルタイムで更新し、各フレームの計算をまとめます。表示ページの再描画は 100ms 以上の間隔で行い、リサイズ停止から 160ms 後にキャッシュ対象ページを更新します。デスクトップ版は初期表示時間、スクロール中の長いタスク、プロセスメモリのサンプリング最大値、HTTP 本文のバイト数を `performance.json` に保存します（直近 20 件）。共有プロセスのメモリ合計では共有ページが重複計上される場合があります。HTTP の値はヘッダーと外部の翻訳サービスへの通信を含みません。

## アーキテクチャ

PDFMathReader はデスクトップの制御、ページの描画、翻訳処理を分離しています。各デスクトップウィンドウには独自のレンダラープロセスとローカルバックエンドがあり、メインプロセスがアプリ全体のサービスを管理します。

```text
                         DESKTOP APP
+--------------------------------------------------------------+
| Electron main process                                        |
| Window lifecycle, native menus, file opening                  |
| Credentials, recent documents, reading preferences            |
+---------------------+----------------------------------------+
                      | IPC via sandboxed preload
                      v
+--------------------------------------------------------------+
| Per-window renderer: Vue 3 + PDF.js                           |
| PDF pages / thumbnails / paragraph overlays / reading state   |
+---------------------+----------------------------------------+
                      | Authenticated HTTP on 127.0.0.1
                      v
+--------------------------------------------------------------+
| Per-window backend: Express in an Electron utility process    |
| Document store / layout analysis / translation queues         |
|                                                              |
| Ultra fast: PDF Inspector --> paragraph translation           |
| Fast / Precise: Python worker --> app-managed math kernels    |
|                                  |                           |
|                                  v                           |
|                         Local OpenAI proxy                    |
+-----------+----------------------+---------------------------+
            |                      | HTTPS: text translation
            v                      v
+----------------------+   +----------------------+
| Local disk           |   | OpenAI API           |
| Translation caches   |   | Translation responses|
| Kernel environments  |   +----------------------+
| Temporary PDF files  |
+----------------------+
```

描画、レイアウト検出、翻訳は独立して実行されます。Python の数式翻訳カーネルはローカルバックエンドのプロキシを通じて OpenAI を呼び出し、API キーはレンダラープロセスに渡されません。認証情報、最近の文書の履歴、保存された設定はメインプロセスが管理し、バックエンドのキャッシュとカーネル環境はローカルディスクに保存されます。

ブラウザでの開発では、ブラウザタブが Electron のレンダラープロセスに代わり、`npm run dev` が独立した Node.js プロセスで Express と Vite を実行します。ネイティブメニュー、デスクトップ IPC、Keychain で保護されたキー保存はデスクトップアプリの機能です。

## 制限事項

- **プラットフォーム対応:** macOS がテスト済みのプラットフォームです。Windows と Linux にはプラットフォーム固有のスタイルがありますが、ネイティブランタイムの検証は保留中です。パッケージ化スクリプトは現在 macOS arm64 向けにのみビルドし、Intel ビルドは提供しません。
- **レイアウトの忠実度:** Ultra fast は幾何学的な段落グループ化とテキストオーバーレイを使用します。複雑な表、回転したテキスト、特殊な背景、長い翻訳では、元のタイポグラフィを維持できない場合があります。数式カーネルの出力は、上流のレイアウト処理に依存します。
- **スキャン文書:** スキャンされた PDF には OCR が必要ですが、このアプリは実装していません。
- **翻訳の要件:** 翻訳には OpenAI API key とネットワークアクセスが必要です。Fast と Precise には、`uv` を通じて別途インストールした数式カーネルが必要です。
- **範囲:** これは実験的なローカルリーダー兼翻訳アプリであり、完全な PDF 編集・書き出しツールではありません。
- **検証:** 自動テストでは、バックエンドとリーダーのサポートロジックを確認します。モックプロバイダーによるチェックでは、実際の OpenAI 翻訳品質や API キーの有効性は確認できません。
